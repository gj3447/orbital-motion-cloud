# 입체운행구름(OMC): 연구 지형과 경계

이 저장소는 8번 사도 **입체운행구름 / Orbital Motion Cloud (OMC)**의 고정 원문 아카이브와 읽기 지도다. OMC는 연구·조직·기술 설계가 만나는 상위 이름으로 기록되지만, 이 안내문은 새 능력·런타임·정전을 만들지 않는다. 원문은 `SOURCE_DOCUMENT`, 여기의 연결·질문·순서는 `SECONDARY_AI`다.

## 정의 색인

여러 문서에 흩어진 “입운구는 무엇인가”를 한곳에 모은다. 각 행의 문장은 연결된 원문을 줄인 것이며,
묶음의 배치와 아래 한 문단 요약은 `SECONDARY_AI`다. 사용자가 구분한 세 관점을 묶는 축으로 쓴다.
KG의 `sym:Character:입체운행구름` 판정 이력에는 약칭 정정(2026-08-30)만 있고 정의를 대체한다는
사용자 판정은 확인되지 않았다. 따라서 아래 정의들은 **대체가 아닌 공존**으로 배치하며,
사용자가 대체를 선언하면 이 표를 고친다.

**한 문단 요약.** 입운구는 agent 시대의 cloud다. 철학적으로는 원리(프로그램)를 실제로 동작하게 하는
에너지이자 존재의 자리이고, 기술적으로는 자유·경제·합의 아래 각자의 토큰·컴퓨팅을 기여해 MHC를 얻고
그것으로 거대 HSWM·CHU의 지능을 이용하는 구조다. 그 구조는 하드웨어 네이티브이며, 의미와 연결은
그대로 두고 작업·데이터·도구의 물리 배치를 실제 장비 조건에 맞춰 계속 리밸런싱한다.

## 정의에서 개발 순서로

정의의 기술 부분은 한 바퀴의 순환으로 읽힌다: **요청 → 비용·신뢰도·이동 속도를 계산한 자원 선택 →
배치·실행 → 결과 검증 → MHC 정산 → 다음 선택에 반영.** 도구 증가는 이 순환이 돌면서 생긴 도구가
다음 요청의 능력이 되는 것이고, 리밸런싱은 순환 중 배치를 다시 맞추는 것이다. 각 구간의 제한형 구현은
이미 있으므로(README의 구현 목록), 새 구간을 늘리기보다 실제로 반복되는 작업 하나를 이 순환 전체에
통과시키고 같은 작업의 전후를 비교하는 것을 우선한다. 이 순서는 `SECONDARY_AI` 제안이다.
작업 단위·선행 관계·기존 계획과의 연결은 [개발 순서 계획](DEVELOPMENT_PLAN.md)에 있다.

## 사용자가 구분한 세 관점

2026-10-10 사용자는 **기술적인 OMC**, **실제 철학적인 OMC**, **디멘션 워커가 보는 OMC**가 각각 다르다고 밝혔다. 아래의 기술·기존 자료 설명을 이 세 관점 전체의 정의로 읽지 않는다. [세 관점과 MIND 원문](OMC_PERSPECTIVES_AND_MIND.md)에 직접 발화와 비행기맨 관련 원문을 연결했다. 각 관점의 세부 내용과 관계는 열린 상태로 남긴다.

## 이름과 층위

철학적·기술철학적 설명은 [OMC 논리 구성](OMC_LOGICAL_FOUNDATIONS.md), 기존 주장과
보완 가정의 구분은 [원문 검토](OMC_FOUNDATION_SOURCE_REVIEW.md)에서 이어진다.
이 논증은 존재·지속·공동 지능과 네 순환의 관계를 전개한 후속 AI 연구다.

이후 사용자는 **자유·경제·합의**를 핵심으로 강조하고, 토큰·컴퓨팅 기여로 얻은 코인으로
지식을 구하는 상대이자 **초거대 통합 CHU에서 동작하는 인지능력체를 비행기맨**으로 명명했다.
[사용자 명명과 기여·지식 순환](RESOURCE_CREDIT_AND_SHARED_INTELLIGENCE.md)을 현행 설명에 반영한다.

- **OMC**는 Orbital Motion Cloud의 약칭이다. `OM`은 이 모듈의 동의어로 쓰면 안 된다. OMC와 OMD를 같은 대상으로 합치지 않는다.
- **OMD**는 Piper/CitC 비유에서 “한 공유 source of truth와 병렬 write 조정” 쪽으로 놓인 별도 조정·데이터 축이다. 반대로 Borg/Kubernetes 쪽은 compute orchestration 축으로 333·ORRR와 연결된다. [KUBERNETES_BORG_ABSORPTION_2026-07-15.md:11-24](../sources/SYMPOSIUM/METAHUMOTONIC/ORBITAL_MOTION_CLOUD/KUBERNETES_BORG_ABSORPTION_2026-07-15.md)
- 따라서 OMC는 OMD의 이름 바꾸기가 아니며, 333·ORRR·engineboy·OM_MANI_PADME_HUM을 한 실행 시스템으로 이미 배포했다는 주장도 아니다.

## 핵심 인격/개념: 기술 갈래보다 먼저

원문은 OMC를 “존재의 사도”로 두고 CHU·AGENT_CLOUD·OM_MANI_PADME_HUM·RUNTIME의 네 위상, 정보=에너지=진동=인프라라는 연결을 제시한다. [SOURCES.md:1-18](../sources/SYMPOSIUM/METAHUMOTONIC/ORBITAL_MOTION_CLOUD/SOURCES.md) 같은 원문은 접근불허의 구름과 CLOUD CONNECT의 서사를 기록하고, 비행기맨만 연결 가능하다는 표현을 보존한다. 이는 신화적/사용자 source 표현이며 현재 access-control 구현 명세가 아니다. [SOURCES.md:18-23, 187-225](../sources/SYMPOSIUM/METAHUMOTONIC/ORBITAL_MOTION_CLOUD/SOURCES.md)

구체적으로 AGENT_CLOUD는 agent들이 모이는 분산 compute substrate로, CHU는 순수 데이터 위상으로 놓인다. OM_MANI_PADME_HUM은 진동의 층, RUNTIME은 다른 원리/프로그램을 동작시키는 에너지의 층으로 설명된다. 이 네 층을 실제 서비스·같은 API·동일한 물리 이론으로 동일시하지 않는 것이 중요하다. [SOURCES.md:67-109, 125-133](../sources/SYMPOSIUM/METAHUMOTONIC/ORBITAL_MOTION_CLOUD/SOURCES.md)

### 333: free P2P substrate와 합의의 국소화

333 자료집은 OMC 휘하의 free/decentralized P2P browser substrate로 설명하고 ORRR의 paid 축과 짝을 이룬다고 적는다. [333/SOURCES.md:1-18](../sources/SYMPOSIUM/METAHUMOTONIC/ORBITAL_MOTION_CLOUD/333/SOURCES.md) PROM 16은 full blockchain·PoW·전역 total order를 cargo-cult로 분류하고, owned-object broadcast, CRDT, content addressing, BFT-CRDT를 별도 설계 후보로 분리한다. 이는 해당 보고서의 설계 판정이며 외부 실험 재현 결과가 아니다. [333/PROM_16_REPORT.md:1-12](../sources/SYMPOSIUM/METAHUMOTONIC/ORBITAL_MOTION_CLOUD/333/PROM_16_REPORT.md)

Kubernetes/Borg 문서는 Piper와 Borg를 먼저 분리한다. Kubernetes의 etcd/Raft는 강한 합의 대조군이고, Omega OCC는 낙관적 동시성·충돌 감지 측의 부분 거울로 제시된다. 같은 문서는 333의 durability, browser substrate, dynamic membership를 남은 프론티어로 적는다. [KUBERNETES_BORG_ABSORPTION_2026-07-15.md:1-18](../sources/SYMPOSIUM/METAHUMOTONIC/ORBITAL_MOTION_CLOUD/KUBERNETES_BORG_ABSORPTION_2026-07-15.md), [333/SOURCES.md:35-52](../sources/SYMPOSIUM/METAHUMOTONIC/ORBITAL_MOTION_CLOUD/333/SOURCES.md)

### OM MANI PADME HUM: feasibility를 구성요소로 쪼개기

P2P substrate, token primitive, cold-start, real-world cases는 별개 파일이다. 그래서 “기술 가능”이라는 한 단어로 합치지 않는다. `A_p2p_substrate`는 browser/WebRTC·libp2p 등 substrate 질문, `B_token_primitives`는 ledger/token 질문, `C_cold_start_sustainability`는 relay·인센티브·지속성 질문, `D_real_world_cases`는 사례 비교를 담당한다. [INDEX.md:1-36](../sources/SYMPOSIUM/METAHUMOTONIC/ORBITAL_MOTION_CLOUD/OM_MANI_PADME_HUM/PROM_16_TECH_FEASIBILITY_2026-05-20/INDEX.md)
