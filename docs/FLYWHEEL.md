# 입체운행구름의 토큰당 지능과 MHC 플라이휠

**출발 전제는 같은 기본 LLM과 같은 총토큰 예산에서, HSWM·CHU를 통해 동작하는 LLM이
단독 사용보다 더 유용한 답변을 만든다는 것이다.** 그 차이가 공동망을 이용할 이유를 만들고,
이용 수요가 자원 기여와 축적을 유도하여 다음 답변의 효율을 높이는 순환을 지향한다.

사용자는 인터넷 데이터 증강에 비유하며 이 전제가 먼저 성립해야 한다고 설명했다.
[발화 원문](../records/2026-10-10/token-efficiency-flywheel/premise-verbatim.txt)은 그대로 보존했다.
아래는 이를 검증 가능한 구조로 풀어 쓴 `SECONDARY_AI` 설계다. 현재 성능 상태는 **미검증 가설**이다.
사용자의 “더 초지능”이라는 방향을 첫 실험에서는 “동일 예산의 과제 해결 효용 향상”으로 측정한다.
이 지표의 성공만으로 범용 초지능을 입증했다고 해석하지 않는다.

## 플라이휠의 순서

[OMC의 철학과 기술철학](OMC_LOGICAL_FOUNDATIONS.md)은 이 기술적 순환을 사람의 요구와
경험, 검증된 기억, 참여 조건의 갱신까지 포함하는 네 순환으로 연결한다. 이 문서는
그중 답변 효율·공동 자원·경제 연결을 검증하는 구체적인 기술 범위를 유지한다.

**토큰당 유용성 향상 → 공동 지능 이용 수요 → 크레딧을 얻기 위한 자원 기여 →
공동 연산과 기억의 가용성 증가 → HSWM·CHU의 선택과 조직 개선 → 토큰당 유용성 향상**

[그래프에서 생성한 순환도](FLYWHEEL_GRAPH.md)는 각 화살표에 해당하는 가설과 조건을 연결한다.

| 연결 | 성립해야 하는 조건 | 확인할 신호 |
|---|---|---|
| HSWM·CHU → 더 좋은 답변 | 필요한 상태·지식·경험·전문화를 고르는 이득이 추가 처리량을 상회 | 같은 모델·총토큰 상한에서 과제 성공률과 효용 차이 |
| 더 좋은 답변 → 이용 수요 | 품질 차이가 가격·대기 시간·신뢰도까지 고려해 유용 | 실제 재이용과 서비스 소비 |
| 이용 수요 → 자원 기여 | 이용자가 기여로 얻는 서비스의 가치가 기여 비용보다 큼 | 합의된 기여 참여와 이탈률 |
| 자원 기여 → 공동 가용성 | 약속한 자원이 실제 작업에 쓰이고 중복 기여를 걸러냄 | 검증된 제공량·가용 시간·작업 완료율 |
| 공동 가용성 → 조직 개선 | 확장된 자원을 필요한 기억·전문화·검증에 연결 | 유용한 작업 처리량과 선택 비용 |
| 이용 결과 → 경험 → 다음 조직 | 결과의 신뢰성과 출처를 확인하고 도움이 되는 변화만 채택 | 새 과제에서 개선 재현, 오염·퇴행률 |

모든 화살표는 조건부다. 단순 저장량·참여자 수·호출 수 증가를 답변 품질 향상으로 계산하지 않는다.
토큰당 이득이 사라지면 더 큰 풀로 확대하기 전에 선택·기억·전이 방식을 고친다.

## 지능 순환과 경제 순환

지능 순환은 **HSWM·CHU의 조직 → 답변 → 사용 결과 → 검증된 경험 → 다음 조직**이다.
HSWM을 단순 검색 도구나 여러 에이전트의 호출 목록으로 한정하지 않는다. 기존 HSWM 개념의
지속적 living harness·world model과 token stream 기반 전이 맥락을 유지하며,
이 연구에서는 그 조직이 답변 효율에 어떤 기여를 하는지 확인한다.
MetaHumo 또한 이 망에서 활동하는 존재이며 개별 LLM 응답 한 번과 동일시하지 않는다.

경제 순환은 **유용한 공동 지능 → 이용 수요 → 합의한 자원 제공 → 기여 대가 → 공동 지능 이용**이다.
MHC는 기여와 소비를 연결하는 경제적 매개다. 상시 공급한 자원의 대가를 나중에 다른 전문화된
MetaHumo의 도움을 얻는 데 사용할 수 있다는 것이 이 구상의 효용이다.
일부 참여자는 주로 공급하고 다른 참여자는 주로 이용할 수도 있다. 모든 이용자가 같은 방식으로
하드웨어를 제공해야 순환이 성립한다고 가정하지 않는다.

MHC의 방향은 **컴퓨팅·AI 자원 이용 가능성을 기준으로 하는 안정성**이다. 달러 고정이나
코인 가격 상승을 이 플라이휠의 성과 지표로 삼지 않는다. 크레딧과 MHC의 표현·교환 비율,
자원 단위, 발행·상환 규칙은 아직 결정하지 않았다. 실제 서비스 수요와 검증된 기여를 연결하는
정산이 필요하며, 보상 발행 자체를 품질이나 지급 능력의 증거로 세지 않는다.

## 첫 검증의 조건

모델 판본·tokenizer·평가 과제·채점 기준을 고정하고, 질의당 동일한 총토큰 상한 B를 둔다.
기본 조건 A는 단독 LLM, B는 같은 자료를 사용하는 일반 검색 증강, C는 HSWM·CHU 방식이다.
**C−A는 전체 연결 효용, C−B는 같은 자료를 조직하는 방식의 추가 효용**을 묻는다.
일반 검색 조건을 추가하는 것은 비교를 명확히 하기 위한 AI 설계 제안이다.

| 조건 | 고정할 것 | 달라지는 것 |
|---|---|---|
| A 단독 LLM | 동일 기본 모델·질문·총토큰 상한·채점 | 외부 기억 없이 답변 |
| B 일반 검색 증강 | A의 조건과 C와 동일한 자료 판본·접근 범위 | 일반 검색으로 문맥 구성 |
| C HSWM·CHU | A의 조건과 B와 동일한 자료 판본·접근 범위 | 관계·상태·전문화·경험을 사용하는 조직 |

T_total은 **모든 LLM 호출의 입력·출력 토큰 합계**다. 내부 에이전트, 문맥 요약, 라우팅,
검증, 재시도·실패 호출과 공급자가 보고하는 추론 토큰을 포함한다. 캐시 입력도 논리적 입력
토큰으로 세고, 이미 출력에 포함된 추론 토큰을 중복 가산하지 않는다. 관측할 수 없는 내부
토큰이 있으면 그 실행은 정확한 동일 총토큰 비교로 판정하지 않는다.

질의별 효용 U는 사전 고정된 과제 채점으로 정의한다. 고정 예산의 주지표는
`평균 U(C, B) − 평균 U(A, B)`이고, 보조 지표는 `ΣU / ΣT_total`이다.
실제 소비량도 함께 보고해 상한만 같고 C가 더 많은 토큰을 쓰는 효과를 숨기지 않는다.
여러 예산에서 품질 곡선을 비교하거나 동일 품질에 필요한 토큰 감소를 측정해 이를 구분한다.
판정 임계값·반복 횟수·신뢰구간 방법은 결과를 보기 전에 정하고, 평균뿐 아니라 과제별 퇴행도 본다.

공동 기억의 사전 구축·학습·갱신 비용은 질의 시 토큰과 분리하여 총량을 보고하고,
관측된 이용 횟수에 따라 상각한 비용도 함께 낸다. CPU/GPU 시간, 메모리·저장장치·네트워크,
대기 시간, 화폐 비용은 별도로 측정한다. 토큰 효율이 곧 전체 컴퓨팅 효율은 아니다.
평가 정답을 공유 기억에 넣지 않고, 평가 중 상태 갱신 여부를 조건마다 고정한다.

## 순환을 키우는 순서

1. 작은 고정 과제 집합으로 A·B·C를 비교한다. 우위가 없으면 어떤 검색·기억·전이가 토큰을 쓰는지 분석한다.
2. 우위가 있는 과제에서 재사용·전문화·관계 선택을 하나씩 제거해 원인을 확인한다.
3. 검증된 유용성을 바탕으로 서비스 소비와 기여의 소규모 정산 실험을 설계한다.
4. 실제 기여·이용·갱신 기록으로 재참여와 개선이 이어지는지 확인하며 풀을 확장한다.

첫 단계가 품질 전제를, 다음 단계들이 원인과 경제 순환을 확인한다. 초기의 기억·지식·연산
구축 비용은 별도의 초기 공급으로 기록해야 하며, 이미 돌고 있는 순환의 수익으로 간주하지 않는다.
자유·경제·합의는 참여와 정산의 원칙이다. 이 실험의 품질 우위가 안전성 전체를 자동 증명하지는 않는다.

## 그래프와 다음 연구의 기준

[그래프 정본](../graph/flywheel.json)은 원문, 개념, 가설, 단계, 지표, 평가를 다른 노드로 보존한다.
[관계 계약](../graph/flywheel-contract.json)은 방향·도메인·범위·기수를 명시한다.
`REQUIRES`만 비순환으로 검사하고, 플라이휠의 `MAY_ENABLE` 순환은 의도적으로 허용한다.
이것은 OMC 저장소 안의 설계 그래프이며 공유 KG 정전 등록이나 HSWM 런타임 구축과 구분된다.

검사와 조회는 `python3 scripts/flywheel.py check` 및 `python3 scripts/flywheel.py query`로 한다.
그림은 정본을 수정한 뒤 `python3 scripts/flywheel.py render`로 다시 만든다.
기존 [자원 기여 목적](RESOURCE_CREDIT_AND_SHARED_INTELLIGENCE.md)의 출발 전제를 이번 연구로 구체화한다.
